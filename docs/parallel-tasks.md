# 多任务并行：一块板怎么同时管几条线

一个项目同时有 3 件事在动时，出错的方式只有四种。这张表就是整个设计的索引——
每条规矩挡一种错，都落在 markdown 文件里，不依赖任何服务。

| 会怎么出错 | 挡它的字段 | 面板上长什么样 |
|---|---|---|
| 顺序乱了：前置没做完就开工 | `after: 3, 4` | 「被挡着」组，卡上写「等 #3」；这类卡不给「我来做」 |
| 两个人抢同一张卡 | `owner: sess-xxx` | 卡头 `👤 sess-a`；只有「交回」，没有「我来做」 |
| 两个人同时改同一块代码 | `scope: src/api, src/export` | 顶部橙色横幅：`⚠ 并行冲突：#3 与 #5 都要动 src/api` |
| 干着干着忘了这次要去哪 | `kind: map` + 四段正文 | 看板最上面的地图卡：去向 / 已经定了 / 还没想清 / 不做什么 |

## 一条主线：地图（kind: map）

一块板最多一张，挂在最上面。正文固定四段，缺哪段就是空，不编：

```markdown
## 去向
大文件导出不再 OOM，边读边写

## 已经定了
用 node 的 stream；先只做 CSV

## 还没想清
断点续传要不要一起做

## 不做什么
这版不碰 Excel
```

子卡用 `parent: 1` 挂上来，卡头显示「挂 2 张」。

这和 matt deck 的 wayfinder 地图是同一个骨架（去向 / 已定 / 雾 / 越界），
差别只在落点：它把地图放进 issue tracker，我们放进 `.pstack/board/`，
因为 pstack 本来就不信「先规划再动手」——地图只记**已经定下来的决定**和
**还没想清的雾**，不预先切票。

## 可开工 = 没做完 + 前置齐 + 没人认领

`frontierOf()` 就是这三个条件。面板把它单独列成「可开工」组，建议引擎
（`src/suggest.js`）也只从这组里挑——被挡着的卡、别人认领的卡**不会**出现在
推荐里。这是「并行不打架」最要紧的一条：推荐本身就是并发闸门。

认领就是开工：点「我来做」= `owner` 写上当前会话号 + 状态转 `doing`。
另一个会话再打开面板，这张卡已经不在「可开工」里了。要交回去点「交回」。

## 冲突检测：路径前缀，不是 AST

```js
covers('src/api', 'src/api/user.ts')  // true
```

两张 `doing` 的卡 scope 有包含关系、又不是同一个 owner，就报冲突。
没写 scope 的在做卡会单独列出来（「没写 scope：#3」），因为面板没法保证它安全。

ponytail：前缀比对挡得住手滑，挡不住「同目录不同文件其实互相依赖」。真遇到
再上 import 图，现在不预支这个复杂度。

## 一个会话干一件事

面板上同时只该有一张 `doing` 是你自己的。要多条线并行，就开多个会话：
每个会话认领不同的卡，scope 不重叠，卡之间用 `after` 连顺序。这不是限制，
是让「谁在动什么」在任何时刻都只有一个答案。

## 收尾：完成要有验证

pstack 的规矩是「做完要证明」。所以卡进 `done` 之前，`verify` 字段该有一行
能重跑的命令或证据：

```
verify: node --test test/*.test.mjs 全绿
```

面板不强制它，但建议引擎会把没验证的完成卡推回 `/prove-it-works`。
