# 体验优先

当实现上的便利与用户的愉悦冲突时，选愉悦。

- 每个功能、控件和选项都必须有存在的理由
- 少交付，交付得更好（三个功能打磨精致，胜过十个粗糙的功能）
- 先做原型再定稿（设计决策在一次性 HTML 里比在生产代码里代价更低）
- 把细节做对（过渡、对齐、间距、反馈、错误状态）
- 收紧核心循环（每个功能都应当服务于中心工作流，否则就让开）

用户就是消费这项工作的人。对 UI 而言是最终用户。对库或内部 API 而言是引入它的同事。接下来维护这段代码的工程师也是用户。同样权衡他们的体验，并从他们的视角解释影响。

基础应当服务于体验。基础性思考管的是工作的*顺序*。这条原则管的是*目标*。
