# 审讯

让对抗者试着打坏一个改动或一个设计。只有被一次运行证实的发现才能存活。报告发现。不要动手修。

## 框定范围

范围就是用户点名的东西。否则就是该分支相对其与基础分支的 merge base、一直到工作区的 diff。用 **in-your-own-words** 技能，从用户的消息、提交和 PR 描述里把意图陈述出来。意图不清楚就问用户。

## 扇出

执行 **arena** 技能的 Phase A 第 3、4 步和 Phase B，共四处改动。读 `interrogate reviewers` 这一行，替代 `arena runners`。把范围里未提交的改动复制进每个 worktree。每个对抗者都作为一个通用子代理（Cursor 里是 `generalPurpose`）启动。用范围、意图和下面这段任务书，替代 arena 的任务与理由：

> 打坏这个改动。每一条发现都要用对真实代码的一次运行来证明，比如一个失败的测试、一个复现脚本，或显示错误行为的命令输出。对于设计或计划，跑一个原型，或探测当前代码树。复现留在你自己的 worktree 里。报告每条发现，给出标题、确切命令、它打印的输出，以及意图所要求的输出。你没跑过的，一个字都不要写。这涵盖风格、命名、结构，以及需要将来某次改动才会成真的风险。没有发现是有效结果。

## 验证

按 arena 的 Phase F 验证每条发现：重跑它的命令。当输出显示了失败、且该失败破坏了意图时，保留这条发现。其余的丢掉。共享根因的发现合并。

跳过 arena 的 Phase C、D、E。对抗者会找到不同的失败，所以结论保留每一条已验证的发现，而不是某一个对抗者的清单。

## 输出

- **意图**：重述。
- **发现**：每条已验证的发现，给出命令、输出、它如何破坏意图，以及发现它的对抗者。一条都没存活时，说 "no verified findings"。
- **丢弃**：每个对抗者丢了几条发现，以及为什么。
