# 测行为，不测实现

一个测试，是对「代码的使用者能通过接口观察到什么」的断言：返回值、错误、他们能读回来的状态，以及对系统外部的效果。私有辅助函数、内部调用顺序、中间数据，都是实现。

用两个假想的改动来判每个测试：

- **弄坏行为**（一个错值，一个被跳过或被做了两次的效果）。测试还过，它什么都没证明。常见成因是断言太松、用被测代码自己算期望值、以及断言测试自己造出来的数据。
- **改内部实现**，所有可观察结果保持不变。测试挂了，它就是被钉在实现上。

留那种能抓住第一个改动、又能扛住第二个改动的测试。其余的改写或删掉。用具体的输入、走公共接口驱动代码，期望值从需求里来。外部服务收到的东西是行为。调用一个内部辅助函数不是。把「这件事永远不会发生」跟一个它确实发生的情形配成一对。断言调用方会据此分支的错误类型，不是错误信息。
