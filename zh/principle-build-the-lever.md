# 造杠杆

当工作不琐碎时，去造那个干活的工具（codemod、脚本、生成器，或一个可重跑的检查），而不是手工做完。门槛是琐碎度，不是重复次数。只有一两处显然的改动才跳过工具。

- 第一个单元手工做，然后造工具，再在那个单元上重跑一遍来证明它。让它能安全地重跑。
- 确定性工具胜过 fan-out。真要 fan-out 时，把 recipe、验证契约和围栏写成同一份技能，让受托的代理读它，且它们不能改它。
- 应用这个原则会产出一个文件。diff 里没有脚本、codemod、生成器或委派技能，就说明你没应用它。当这项工作的寿命超过这次会话时，把它提交。
- 造能完成或能证明这件事的最小脚本，永远不要造框架。
