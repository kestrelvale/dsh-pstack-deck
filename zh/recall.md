# 回忆

**在开始或恢复工作之前，你重建用户近期的工作上下文，交回一个紧凑的胶囊：现在处在什么位置，接下来做什么。**

保持紧凑、切题。只读范围内线索需要的东西，然后停下。

你的上下文存在于两份记录里。你自己的聊天历史保存你做了什么、决定了什么。共享记录保存围绕同一段代码、以其他名义发生的一切：用户反复报告的症状、已上线又被回滚的修复、生产里仍在报的错。第二份记录存在于版本控制、工单系统、聊天与工单频道、长文档和错误追踪里。一个带着长长 bug 尾巴的功能，大部分故事都在那里，所以别只靠你自己的转写记录去重建它。

转写记录存在你的宿主存放它们的地方。每个文件是 JSONL。找到你这个宿主对当前活动工作区使用的目录。如果你分不清自己是哪个宿主，就看这个工作区里存在下列哪一种：

- **Cursor：** `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`。`<slug>` 是工作区路径去掉开头的斜杠、并把每个 "/" 换成 "-"（`/Users/you/proj` 变成 `Users-you-proj`）。
- **Claude Code：** `~/.claude/projects/<slug>/<session-id>.jsonl`。`<slug>` 是工作区路径中每个非字母数字字符都换成 "-"（`/Users/you/proj` 变成 `-Users-you-proj`）。
- **Pi：** `~/.pi/agent/sessions/--<slug>--/<timestamp>_<id>.jsonl`。`<slug>` 是工作区路径去掉开头的斜杠、并把每个 "/" 换成 "-"（`--Users-you-proj--`）。
- **Codex：** `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`，不按工作区分组。只保留第一行里 `payload.cwd` 等于该工作区路径的文件。
- **OpenCode：** `~/.local/share/opencode/storage/`。会话是 `session/<project-id>/` 下的 JSON 文件，其消息在 `message/` 与 `part/` 下。

1. 先分类，再路由。要恢复某一次具体的既往聊天，那是 `session-pickup` playbook，不是这个。把习惯变成一项长期技能是 `automate-me`。把工作写成给人读的摘要是另一件事。Recall 是在你动手之前，跨最近若干聊天加载工作上下文。如果用户已经给了你完整的状态胶囊（路径、分支、改动），直接用，跳过挖掘。
2. 搜索之前先锁死范围。钉住窗口（"最近"是一个真实区间，默认过去 7 天）、点名的话题，以及工作区（默认当前活动的那一个。未经要求，绝不读别的项目的转写）。把范围复述回去。绝不悄悄把"全部"变成"最近 N 个"。
3. 在聊天历史里扇出。用快速、便宜的模型起并行子代理，每个吃语料的一块。告诉每个子代理：候选按真实修改时间（`ls -t`）排序，绝不按 UUID 名；先 grep 话题，然后只读匹配的聊天、只读其中相关的区段；跳过当前聊天以及明显的噪声（子代理、eval、测试聊天）。每个都返回同一套结构，每个聊天一块：话题、用户的目标、决策、未结线索、磕碰与纠正、产物（PR、工单、分支），每条都标注聊天 UUID。只有一两个聊天时，跳过扇出，直接搜。原始转写留在子代理那里。主线程只拿它们的发现。按 **poteto-mode** 技能里 Subagents 一节，为任务挑每个子代理的推理档位。
4. 只要话题点名了某个功能、文件、子系统、领域或 bug，就扫一遍共享记录。这是默认动作，不是判断题，而且"我在 X 上的工作"不能豁免它。每个来源起一个调查子代理，用 agent 模式，因为 readonly 会剥掉 MCP 访问，逐个问它们"当前状态是什么、试过什么但没立住、用户还在报什么"。让它们与聊天历史挖掘并行跑。空结果也是发现。某个 MCP 不可用就跳过并说出来。把回来的东西并入简报。只有纯粹的活动回顾、且没有点名对象时（"我这周做了什么"），才跳过这一步——那种情况下你自己的历史和实时状态就是全部答案。
5. 对照实时状态验证。把挖掘与扫查浮现的 PR、分支、工单拿 `git` 和 `gh` 核一遍。当答案取决于某个代理实际做了什么（跑了哪些工具、读了哪些文件、撞了哪些错）时，读完整转写，而不是本地剪裁过的副本。
6. 按下面的契约写简报。按线索分组。守住点名的话题。

## 输出契约

开头是胶囊，然后是线索状态，然后是问题，然后是下一步动作。更深的细节放后面，或者砍掉。

- **胶囊。** 最多 5 条。这项工作是什么，整体处在什么位置。
- **线索。** 每条一行，前面恰好一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。没有标签的线索就是还没做完，给它打上标签。
- **问题。** 最多 5 条，反复出现的那些。把用户反复报告的症状、以及上线后又被回滚的修复都写进去，让下一次尝试从上一次失败的地方开始。
- **下一步。** 最有用的那一个下一步动作，要具体。

相邻的功能或工单不写进来，除非它阻塞这一项。当胶囊和线索行超过一屏时，先砍细节，再砍线索。通过 **unslop** 技能写简报，聊天里的发现用 UUID 引用，共享记录里的发现用它们的来源引用（PR 号、工单 ID、聊天永久链接、错误追踪条目），任何对外输出之前先把私有上下文脱敏。

**回复：** 按上述契约给出简报。
