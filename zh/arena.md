# Arena

在启动任何东西之前，先开一个待办清单，每个阶段一条（Frame、Fan out、Cross-judge、Pick、Graft、Verify）。

## 阶段 A：框定

每个候选拿到的都是同一份提示词，所以提示词就是契约。

1. 说明每个候选要产出的产物是什么。
2. 推导评分表：3-6 条具体的、可打分的标准，说明在*这个*任务上什么样算成功。它是阶段 D 里挑选者的工具。候选只看得到任务。
3. 从 pstack 设置文件的 `arena runners` 行里选跑手（Cursor 里是 `~/.cursor/rules/pstack-models.mdc`，Claude Code 里是 `~/.claude/rules/pstack-models.md`，其他宿主是 `~/.agents/pstack-models.md`），默认是 `claude-fable-5-2-high`、`claude-opus-5-5-high-fast` 和 `gemini-4-neon-xhigh`。`auto` 或 `inherit-parent` 这种条目指的是父模型，所以省掉 `model`，起一个通用子代理（Cursor 里是 `generalPurpose`）。如果你的子代理工具拒绝某个 slug，就用它报错信息里同族最近的合法 slug，或者你宿主的模型列表里的那个；再不行就撤掉这个席位，至少保留两个跑手，并说出来。族按前缀划分，最长匹配优先：`claude-fable-*`、`claude-*`、`gemini-*`，先去掉开头的 `cursor-`。其他任何 slug 的族就是第一个连字符之前的文本。要多个设计方向就多起几个；当活儿是生成密集型而不是判断密集型时，重复用同一个模型。每个子代理的推理档位按 **poteto-mode** 技能的 Subagents 一节来选。
4. 给每个候选自己的输出位置（尽可能地用 git worktree，否则用 `/tmp/arena-<slug>/candidate-<n>/`），按 **separate-before-serializing-shared-state** 原则技能来做。

## 阶段 B：扇出

在一条消息里用 `run_in_background: true` 起全部 N 个子代理，每个都带上任务、共享依据的路径、它自己的输出路径，以及一段指令：产出产物，并附一份简短的理由，说明它考虑过哪些备选、否决了什么。

如果某个候选没有产出，就以 N-1 继续，并记录这个掉队者。

## 阶段 C：交叉评判

等阶段 B 的全部候选完成后，从 pstack 设置文件的 `arena cross-judge pool` 行里起一个只读评审（Cursor 里是 `~/.cursor/rules/pstack-models.mdc`，Claude Code 里是 `~/.claude/rules/pstack-models.md`，其他宿主是 `~/.agents/pstack-models.md`），默认是 `claude-opus-5-5-high-fast`、`gemini-4-neon-xhigh`。评审绝不来自父模型的厂商，在这项检查里 Fable 算作 Claude，所以用另一家厂商的第一个条目。`auto` 或 `inherit-parent` 条目指的是父模型。如果你不知道父模型是什么，就用第一个真实 slug，并说明厂商检查没有跑。如果你的子代理工具拒绝某个 slug，就用它报错信息里同族最近的合法 slug，或者你宿主的模型列表里的那个，再不行就用下一个这样的条目；也可以跳过评审，并说出来。你在阶段 D 阅读的同时，评审按路径标签给每个候选在每条评分标准上打分，并推荐一个基线。

## 阶段 D：选基线

挑选之前，把每个候选从头到尾读完。逐条对照评分标准给它打分，而不是凭整体感觉，并在阶段 C 跑过评审时跟它比对。对基线的判断一致，就确认这次挑选。不一致，说明你们其中一个有偏见，或者评分表有歧义。做决定之前把两份理由都读完。

挑一个未来的维护者最容易扩展、又不会破坏不变量的基线。两个打平时，按懒惰协议优先选边界更干净或 API 更小的那个。

## 阶段 E：嫁接

把每个落选候选再走一遍，找值得移植进基线的东西，通常每个候选一两条，而不是大部分。每一处嫁接都手工折进去，按 **redesign-from-first-principles** 原则技能来做，让结果在同一个心智模型下保持连贯。不要机械粘贴。

如果候选收敛到同一个形状，那是很强的一致意见。记下来，直接交付这个共识形状。不需要嫁接。如果它们差异极大，说明阶段 A 框得不够细。重新框定并重跑，而不是把分歧平均掉。

## 阶段 F：验证

像验证任何其他输出一样验证合成出来的产物，按 **prove-it-works** 原则技能来做。如果验证发现了 arena 漏掉的问题，要么是阶段 A 错了（重新框定并重跑），要么是某个候选抓到了而你漏了那处嫁接（回到阶段 E）。不要糊过去。

## 产出

一个合成出来的产物，旁边附一份简短的合成说明：基线是哪个以及为什么、交叉评审的裁决或阶段 C 跳过了评审这一事实、每一处嫁接及其来源候选、否决了什么以及为什么、任何收敛或掉队、以及验证结果。
