# Correct

运维者一直在为同样的错误反复纠正这个仓库里的代理。改变仓库，让下一个代理犯不了这些错。

假定每个贡献者都是代理：它只看得见自己打开过的文件，会抄最近的例子，会走能编译的最短路径。把仓库设计成「从一个文件看是对的改动，对整个仓库也是对的」。

## Find the mistake classes

先读近期的提交、回退、评审意见、代理指令文件，以及解释变通做法的注释。把错误归成类别。一个类别发生过两次才算数。

## Fix each class at the highest level that works

1. **用架构消除它。** 让每份状态只有一个主人，每件事只有一种受支持的做法。把内部藏起来，让错误的导入直接失败。用手工同步的列表换成一个唯一事实来源。删掉代理会照抄的旧做法和死代码。
2. **用类型强制它，让坏状态写不出来。** 如果坏代码仍能编译，就加一条 lint 或 CI 检查，让它的报错点名该改用哪个文件、类型或函数。如果这种模式已经很普遍，只在某次改动让它变多时才失败。
3. **测行为。** 凡是它检查的行为坏掉后仍会通过、或者只有内部实现变化就会失败的测试，修掉或删掉。
4. **最后才写文档或代理规则，而且只针对判断题。** 代理跳过它们时什么都不会失败。

## Fix and prove

然后现在就修掉最高频的那些类别，一个提交修一个。证明每条新检查都会在真实的过往错误上失败。在本地和 CI 里跑同一条命令。例外写在出问题的那一行上，附上理由、过期日期和某个人类的批准。

## Keep the rule table

最后，在代理的指令文件里维护一张表，把每条规则和强制执行它的东西配对。当运维者纠正你时，修掉那个错误并把规则加进去。如果规则本来就有、而没有任何东西在强制它，那就是一次重复，所以在同一次改动里按最高层级修掉。一旦某个错误再也不可能发生，就把对应的规则删掉。

**Reply:** 每个类别连同它的证据、你选的层级、以及更高层级为什么不行。
